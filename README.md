# cyberfondo

자전거 대회 참가 기록을 자동으로 수집해 구글 스프레드시트에 적재하는 파이프라인입니다.

디시인사이드 로드싸이클 갤러리에서 열리는 장거리 라이딩 대회('사이버폰도')는 참가자가 갤러리에 글을 올려 기록을 제출합니다. 운영자가 그 글들을 하나씩 읽고 시트에 옮겨 적어야 했고, 참가자마다 기록을 쓰는 방식이 제각각이라 손이 많이 가는 일이었습니다. 그 반복을 없애려고 만들었습니다.

지금은 개인 서버에서 Supervisor로 상시 실행 중입니다.

## 흐름

```
[갤러리 목록 수집]
      │  요청 사이 무작위 딜레이(2~5초), User-Agent 지정
      ▼
[본문 조회] ── 첫 줄이 대회 패턴으로 시작하지 않으면 버림
      │
      ├─ 기록 추출 ──── 정규식
      │                 시간 · 거리 · 획득고도
      │                 "7:53" / "7시간54분" / "07:54:30" 등 표기 차이를 흡수
      │
      ├─ 스트라바 링크 추출 ── 정규식
      │
      └─ 사연 요약 ──── Gemini (실패 시 원문 앞부분으로 폴백)
      │
      ▼
[구글 시트 적재] ── 점수 계산 수식과 함께 행 추가
      │
      ▼
[운영자 검수] ── 스트라바 기록과 교차 확인 후 '완료' 입력
      │
      ▼
[점수 확정] ── 검수를 통과한 행만 점수가 계산됨
```

## 설계에서 신경 쓴 것

**규칙으로 되는 건 규칙으로 처리합니다.**
기록 값(시간·거리·고도)은 형식이 흔들려도 결국 숫자라서 정규식으로 뽑고 정규화합니다. 참가자들이 `사이버폰도 7:53 340 3400`처럼도 쓰고 `사이버 폰도, 7시간54분, 340km, 3400m`처럼도 쓰는데, 이 정도 변형은 패턴으로 흡수됩니다. 여기에 LLM을 쓰면 비용과 지연만 늘고 틀릴 여지가 생깁니다.

**규칙으로 안 되는 것만 LLM에 맡깁니다.**
참가자들이 기록과 함께 적는 후기는 형식이 없습니다. 이건 정규식으로 다룰 수 없어서 Gemini에 맡겨 한 문장으로 줄입니다. 갤러리 특유의 말투를 살려 달라는 지시를 프롬프트에 넣었습니다.

**LLM이 실패해도 파이프라인은 멈추지 않습니다.**
API 키가 없거나 호출이 실패하면 원문 앞부분을 잘라 넣고 계속 진행합니다. 요약이 없다고 기록 적재까지 막힐 이유는 없습니다.

**최종 판단은 사람이 합니다.**
수집된 기록은 그대로 점수가 되지 않습니다. 운영자가 스트라바 기록과 대조해 검수 칸에 '완료'를 입력해야 점수 계산 수식이 동작합니다. 자동화가 반복을 걷어내고, 판단은 사람에게 남겨 뒀습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `crawler.py` | 갤러리 수집, 본문 파싱, 기록 정규화, 사연 요약 |
| `sheets_manager.py` | 구글 시트 적재 |
| `auth_setup.py` | 구글 API 인증 초기 설정 |
| `config.py` | 환경 변수 로딩 |
| `main.py` | 실행 진입점 |
| `supervisor/cyberfondo_crawler.conf` | 상시 실행 설정 |

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env      # 시트 ID, Gemini API 키 등 입력
python auth_setup.py      # 구글 API 인증 (최초 1회)
python main.py
```

### 재검사 (파싱 규칙 변경 후 지난 글 다시 싣기)

패턴 불일치로 스킵된 글은 시트엔 안 실리지만 `seen_posts.json`에는 "확인함"으로 기록돼서, 정규식을 고쳐도 다음 스캔에서 자동으로 다시 검사되지 않습니다. 이럴 때는:

```bash
python main.py --retry-skipped
```

`seen`에는 있지만 시트(K열)에는 없는 URL만 골라 재검사 후 종료합니다. 상시 실행 중인 Supervisor 프로세스와는 별개로, 필요할 때 수동으로 한 번 실행하면 됩니다.

### 특정 글 하나만 처리

```bash
python main.py --post 1124284
# 또는 URL 그대로
python main.py --post "https://gall.dcinside.com/mgallery/board/view/?id=cycle&no=1124284"
```

게시글 번호나 URL 하나를 지정해서 그 글만 조회·파싱 후 종료합니다. 특정 글이 왜 스킵됐는지 확인하거나, 정규식을 고친 뒤 그 글 하나만 바로 확인하고 싶을 때 씁니다. 시트에 성공적으로 적재된 경우에만 `seen_posts.json`에 기록되고, 실패/스킵은 기록하지 않아 다음 정기 스캔이나 `--retry-skipped`에서 다시 시도될 수 있습니다.

`credentials.json`, `token.json`, `.env`는 저장소에 포함되지 않습니다.
